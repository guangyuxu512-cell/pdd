# 客观建议

1. 第一版先跑通单机多店铺，不要先做分布式。当前并发 3-5 个店铺时，SQLite + WAL + 店铺锁足够。
2. 平台能力必须插件化。核心壳只保留店铺、Profile、任务、日志、AI、验证码，不要把具体平台业务逻辑写进核心层。
3. 浏览器只负责登录态，业务请求尽量走 HTTPX。这样日志、重试、限流、失败归因都更可控。
4. AI 只能输出建议和草稿，不能直接执行平台动作。尤其是售后回复、商品清理、推广调整，都应保留人工确认或规则确认。
5. 验证码第一版只做人工接管流程。先保证任务可暂停、可恢复、可记录，再考虑第三方或自建识别。
6. 数据不要放安装目录。数据库、Profile、截图、日志、导出文件都放用户数据目录，方便升级和备份。
7. 所有核心表提前带 `platform`、`shop_id`、`account_id`、`profile_id`、`worker_id`。这是以后扩展多电脑和中央库的关键。
8. 不要每个店铺打包一个 exe。一个程序包管理多个店铺，店铺只是运行时配置。
9. 尽早加备份和迁移。SQLite 每日备份、升级前备份、Alembic 迁移，比后期补救成本低。
10. 前端系统设置要尽早做，至少包含数据库、AI、浏览器、并发、代理、日志、插件开关。
