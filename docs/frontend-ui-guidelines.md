# 前端 UI 统一规范

## 布局

- 左侧菜单只放功能入口，右侧为当前功能工作区。
- 每个功能页使用一个 `.panel` 作为主容器，主容器高度固定填满业务日志上方空间。
- `.panel-header` 放页面标题、核心筛选条件和右侧数量 badge。
- `.panel-body` 放操作按钮和数据表格。
- 数据表格必须放在 `.data-table-wrap` 或功能专属表格容器里，滚动条只出现在表格内部，不允许页面外层滚动。
- 列表页的表格区域必须固定在业务日志上方空间内，数据增加时只在表格内部滚动或分页，不允许撑开页面。
- 查询工具条按实际控件宽度排布，不允许单个输入框无意义占满整行。

## 表格

- 表格使用固定布局：`table-layout: fixed`。
- 表格即使没有数据也必须显示固定表头，空状态只能出现在表体内。
- 行高固定，默认 `38px`，图片、按钮、长文本不能撑高行。
- 高频列表可以使用更紧凑行高，但必须保持列宽、表头和单元格对齐稳定。
- 表头和对应单元格默认居中对齐，保持整齐一致；只有极少数明确需要左对齐的长文本列才单独覆盖。
- 第一列如为复选框，宽度保持窄列并居中。
- ID 如只是展示序号，使用 `1, 2, 3...`，并居中。
- 长文本列允许截断或自然换行，但不得撑破表格。
- 被截断的日期、ID、长文本必须通过鼠标悬停显示完整内容。
- 图片列默认展示固定尺寸缩略图，缩略图悬停显示眼睛入口，点击打开弹窗预览；缩略图不得撑高表格行。
- 数字统计列需要排序时，使用表头点击排序，并显示当前升降序状态。

## 控件

- 下拉框统一使用 `.ui-select`。
- 复选框统一使用 `.ui-check` 或全局 `input[type="checkbox"]` 样式。
- 操作按钮高度统一，短按钮也要保持一致宽度。
- 主要动作使用 `.primary`，危险动作使用 `.danger`。
- 禁用态必须使用 DOM `disabled` 属性，不允许字符串模拟。

## 行为

- 点击“获取”类按钮后，按钮进入禁用态并显示进行中状态。
- 长任务必须输出分页/进度日志，不能只有开始和结束。
- “停止”只保留停止前已经完成的数据，停止后返回的数据必须忽略。
- 新增功能的筛选条件在当前页面刷新渲染后必须保留。
- 可能产生大量数据的列表必须提供每页数量选择和翻页控件。

## 日志

- 业务日志旧消息在上，新消息追加到下方。
- 页面渲染后日志滚动到底部。
- 请求过程中的关键进度必须写入日志。

## 状态与误操作保护

- 商品、SKU、活动 ID、PXI 等业务表默认只展示可操作的有效数据；已删除、失效、商品已删除等状态必须通过筛选项显式查看。
- 状态筛选的默认项命名为“有效...”或“有效数据”，不能用“全部状态”表示默认过滤后的列表。
- 已删除或失效的数据即使在筛选后可见，也不能参与全选、勾选、报名、同步等后续操作。
- 活动 ID 与商品/SKU 一样采用软删除或失效标记，保留历史记录用于追溯，默认不在前端展示和选择。
- 所有可能执行外部请求或报名动作的按钮，在执行前必须校验店铺 cookie 状态、商品状态、SKU 状态和活动状态。
